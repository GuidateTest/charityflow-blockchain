SWC-106: Unprotected SELFDESTRUCT Instruction

Group A — Lab 7 DApp Security | MDT915

1. What is SWC-106?

SWC-106 identifies smart contracts where the selfdestruct instruction can be called by anyone due to missing or insufficient access controls.

AttributeValue
SWC IDSWC-106
TitleUnprotected SELFDESTRUCT Instruction
CWECWE-284: Improper Access Control
SeverityHigh / Critical
Definition (SWC Registry):
"Due to missing or insufficient access controls, malicious parties can self-destruct the contract."

7. Code Examples

7.1 Vulnerable Code (SWC-106)

// ⚠️ VULNERABILITY: No access control
function destroy(address payable _to) external {
    selfdestruct(_to);  // Anyone can call!
}

7.2 Fixed Code (Remediation)

// ✅ FIXED: OpenZeppelin Ownable
import "@openzeppelin/contracts/access/Ownable.sol";

function destroy(address payable _to) external onlyOwner {
    require(_to != address(0), "Invalid recipient");
    selfdestruct(_to);
}

8. Parity Wallet Incident (Real-World)

In 2017, a user accidentally called initWallet() on the Parity multi-sig library, making themselves "owner", then called kill() which executed selfdestruct. Result: ~$300M in ETH frozen.

Parity Postmortem

9. Remediation Checklist

  • Remove selfdestruct unless absolutely required
  • If needed: add onlyOwner or role-based access (e.g. AccessControl)
  • For high-value contracts: use multisig (Gnosis Safe)
  • Run Slither/Mythril to detect SWC-106

10. Reflection / Key Takeaways

  • SWC-106 = Unprotected SELFDESTRUCT — critical if anyone can call it
  • Remediation: Always protect selfdestruct with onlyOwner or role-based access
  • Best practice: Remove selfdestruct if not needed; use multisig for high-value contracts
  • Real-world: Parity wallet incident ($300M frozen) — init + kill = disaster
